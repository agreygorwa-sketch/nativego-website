How to read this page

A requirement is one thing the system must do. "FR" means Functional Requirement — a function is a thing the system does. Each row shows: Input (what you type or click), Process (what the system does with it), Output (what you see after), and Table (where it is stored in the database).

What "hash password" means (FR-01, FR-02)

Hashing turns a password into a long jumble of letters and numbers that cannot be turned back into the password. The database stores the jumble, never the real password. When you log in, the system hashes what you typed and checks if the two jumbles match. That is why a stolen database does not give away passwords.

What "session" means (FR-02, FR-15)

A session is the system's short memory that you are logged in. After you log in, it gives your browser a session so you do not have to type your password on every page. Logging out clears it.

Non-functional requirements (Table 4.2)

Functional requirements say what the system does. Non-functional requirements say how well it must do it, across all roles. The table below is the document's own: Table 4.2, Non-functional requirements of the NativeGo web platform.

IDRequirement and targetWhy it matters to this system
NFR-01Performance: pages load in under 3 seconds on modest mobile connectionsTourists on mobile data abandon slow pages; speed decides adoption (Emam & Abdelaal, 2021)
NFR-02Security: passwords salted and hashed; parameterized queries; server-side role checks on every routeThree roles and user-supplied content make this the sharpest risk (OWASP Foundation, 2021)(Alghawazi et al., 2022)
NFR-03Usability: responsive interface, usable on phones, tablets and desktops with no trainingEase of use drives booking intention (Emam & Abdelaal, 2021)(Li et al., 2022)
NFR-04Privacy: location collected only where a feature needs it; never exposed beyond the parties to a requestLocation data is sensitive and shapes continued use (Rodríguez-Priego et al., 2022)(Choi et al., 2023)
NFR-05Reliability: consistent behaviour under repeated and concurrent use; no data loss on failureA platform that loses requests loses trust
NFR-06Compatibility: runs in any modern browser; no download or installationRemoves the biggest adoption barrier for short-stay tourists (Jagatha et al., 2023)
NFR-07Maintainability: modular code (Flask blueprints per module); normalised schemaOne module change without disturbing the rest (Bednarz & Miłosz, 2025)(Hardini et al., 2025)

How this site honours them: it is plain HTML, CSS and JavaScript with no heavy libraries, so pages stay light and fast (NFR-01); the layout stacks into one column on a phone and works on any screen with no training (NFR-03); it runs in any modern browser with nothing to install (NFR-06); and location is only asked for where a feature needs it — the guide search — never anywhere else (NFR-04). Passwords, role checks and database queries live on the live system, not on these pages (NFR-02).
